# Review conventions (example)

Copy this file to your project root as `.review-bus.md` and edit it, then commit it.
The Codex reviewer reads `.review-bus.md` from your PR's base ref and enforces the
conventions you list here. If the file is absent, a generic review is used.

Keep it short and project-specific — point at your real standards rather than
restating them:

> Enforce this project's coding conventions from its CONTRIBUTING / CLAUDE.md /
> AGENTS.md and any docs they reference. In particular: <your language/framework
> rules — e.g. layering, naming, error handling, required tests, formatting,
> security invariants>.
>
> Focus reviews on correctness, security, and the project's documented invariants.
> Skip subjective style the linter already enforces. Flag missing tests for new
> behavior.
